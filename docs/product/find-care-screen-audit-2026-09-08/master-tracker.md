# Find-care screen audit — master tracker

Audit date: **2026-09-08**. Scope: family finding care, one-time and recurring, from creation through closed records. **Post-implementation local UI inventory and screenshots.**

[Open visual screenshot browser](<index.html>) · [Machine-readable capture manifest](<captures.json>)

[Run the local app and sign in by role](<local-access.md>) · [Original September 7 baseline](<../find-care-screen-audit-2026-09-07/master-tracker.md>)

**319 of 319 screen states have verified desktop + mobile evidence. 1914 screenshot files are linked.** Each captured state has a first-screenful and full-page PNG at each viewport, plus rendered text and a structured information inventory. Focused PNGs begin at the page heading where available; gallery previews use these to make the workflow easier to inspect.

Desktop: 1440 × 1000. Mobile: 390 × 844, touch/mobile emulation. Browser: headless Edge Chromium, DPR 1. The application was captured after the current Vite build using isolated synthetic audit data. Remote map and payment widgets were blocked for the local capture session; Brand fonts are served locally. Visible widget fallback states are part of the evidence. A captured screen does not validate a third-party payment or map interaction.

A stage is a customer step; a screen state is a specific route, selected tab, disclosure/panel state and data condition. Recurring care has both an arrangement lifecycle and a dated-visit lifecycle. A closed visit can belong to an active recurring arrangement.
