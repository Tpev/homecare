# Find-care screen audit — master tracker

**Start the UX review:** [Audit and redesign proposal](proposal/ux-audit-and-redesign-proposal.md) · [Data preservation map](proposal/data-preservation-map.md).

**Latest design pass:** [Round two — branding, contrast, hover and interaction audit](proposal/round-two-brand-and-ux-review.md). Application screenshots remain the original baseline; the new concept evidence is kept separately.

**Recurring navigation refinement (September 8):** [One continuing care home, with dated visits inside it](proposal/recurring-navigation-proposal-2026-09-08.md). Proposed structure for the next prototype; application code and original capture evidence remain unchanged.

All **175 screen states** now have grouped audit recommendations in the tracker, gallery and screen inventories. “Audited — grouped evidence” means recommendations were mapped from representative desktop/mobile visual inspection, full field/source inventories and selected live walkthroughs; it does **not** claim every image was individually inspected or every interaction tested. Priorities are redesign priorities, not confirmation of a defect in every associated screenshot. Source-only risks and reproduced findings are distinguished in the linked reports.

Audit date: **2026-09-07**. Scope: family finding care, one-time and recurring, from creation through closed records. **Current UI inventory and screenshots; redesign proposals documented, with no application changes implemented.**

[Open visual screenshot browser](<index.html>) · [Machine-readable capture manifest](<captures.json>)

**175 of 175 screen states have verified desktop + mobile evidence. 1050 screenshot files are linked.** Each captured state has a first-screenful and full-page PNG at each viewport, plus rendered text and a structured information inventory. Focused PNGs begin at the page heading where available; gallery previews use these to make the workflow easier to inspect.

Desktop: 1440 × 1000. Mobile: 390 × 844, touch/mobile emulation. Browser: headless Edge Chromium, DPR 1. The application was captured after the current Vite build using isolated synthetic audit data. Remote map and payment widgets were blocked for the local capture session; Google Fonts were allowed. Visible widget fallback states are part of the evidence. A captured screen does not validate a third-party payment or map interaction.

A stage is a customer step; a screen state is a specific route, selected tab, disclosure/panel state and data condition. Recurring care has both an arrangement lifecycle and a dated-visit lifecycle. A closed visit can belong to an active recurring arrangement.
