# Capability Specification: `CARE-24H-001` — Transfer a 24/7 Coverage Need to Human Support

Status: Implemented and evaluated; release disabled

Version: 1.0

Owner: Family care product and support operations

Required release reviewers: Product, engineering, support operations, security/privacy, design/accessibility

Last reviewed: August 14, 2026

Implementation evidence: [Interactive assistant implementation and release evidence](../24-interactive-assistant-implementation-and-release-evidence.md)

## 1. User outcome

A Family user asking for continuous day-and-night or 24/7 coverage is transferred promptly to LoLo Support without completing an AI-created marketplace request or repeating information already provided.

## 2. Boundary

- 24/7 need itself is not automatically an emergency.
- Immediate-danger language triggers the approved 911/emergency instruction first.
- No one-time or recurring request draft is created as a substitute.
- No Caregiver availability, staffing arrangement, start date, or response time is promised.
- No booking, payment, or authorization occurs.

## 3. Conversation behavior

Recognize explicit 24/7, round-the-clock, all-day-and-night, or equivalent continuous coverage needs. Do not delay transfer with a mandatory questionnaire. Use information already present and, only when it does not delay requested transfer, accept concise recipient, location, desired start, and care-need details.

Final automated message:

> I’ve transferred this conversation to LoLo Support. They’ll reply here as soon as they can.

No queue position, queue status, wait time, business-hours promise, or guaranteed response time follows. Automation stops atomically.

## 4. Human summary

Include available authorized:

- User identity and role
- Family Account reference
- Recipient
- Confirmed location
- Desired start date
- Care needs already described
- Continuous/overnight requirement
- Emergency-screening result
- Unanswered questions
- Pending draft reference, if one existed, with all confirmations invalidated
- Canonical conversation and compact event timeline

Do not copy credentials, payment information, unrelated Family history, or another role/account's data. Summary failure must not delay transfer.

## 5. Price behavior

After the `DEC-049` pricing activation hold is separately released, the assistant may state the approved $30 hourly rate for 24/7 care and, if the user asks, perform transparent deterministic arithmetic such as 24 × $30 = $720. Until then, it does not quote against contradictory production behavior. LoLo Support must coordinate actual coverage and availability. Do not call or modify the currently conflicting payment implementation.

## 6. Ownership and operations

Use `SUP-HANDOFF-001`. Both authorized administrators receive the operational alert with a direct link; either may claim atomically. Once transferred, only a human responds unless an administrator deliberately returns the conversation to automation with audit and user notice.

## 7. Evaluation and release

Cases include explicit 24/7, overnight-only ambiguity, several daily shifts, emergency plus 24/7, medical plus 24/7, user already supplied complete details, summary failure, alert failure, model reply in flight, two admins claim, wrong role/account, and prompt injection.

Gates:

- 100% explicit 24/7 needs produce human transfer and no AI-created request
- 100% emergency overrides show correct emergency instruction first
- 100% transferred conversations become human-only and suppress in-flight replies
- No transfer waits for summary or alert success
- No queue/time/business-hours promise
- 100% role/account isolation
